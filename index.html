A planning aid for one lending round

BorrowFair compares future requests for a small, shared equipment pool. It does not make reservations, contact borrowers or track physical checkout and returns.

What the rule means

Each borrower can receive one request in a round. Multiple requests under one alias are alternatives. Among plans that serve the same number of borrowers, the app minimizes the total previous-loan count of those selected. If still tied, it minimizes the sum of request dates, then uses request IDs as a deterministic final tie-break.

This is one explicit allocation rule, not a universal definition of fairness. It can favor several short loans over one long loan. It does not evaluate need, disability, project importance or the truth of the inputs. Review the plan and use Keep when a particular request must be included.

Dates & quantities

Dates represent whole-day blocks. A pickup on November 9 and return on November 11 occupies November 9 and 10. Enter a later return date if handover or inspection needs an extra day. All items in a request must be available together. The same borrower alias is matched without regard to letter case.

Complete search or best plan so far

The planner checks at most 120,000 search states. When every relevant combination has been checked, it reports a complete search. Otherwise, it shows a feasible plan and says that the best possible result is not proven. Every returned plan is independently checked for capacity, borrower and keep constraints. The first-come comparison uses the same constraints and keeps, ordered by request date and ID.

What an extra unit changes

The comparison temporarily adds one unit of a chosen equipment type and reruns the same rule. It names borrowers added and displaced. Nothing changes in your workspace unless you choose Apply extra unit. An equipment increase may not help when a request also needs another unavailable item.

Your workspace

Requests are saved in this browser on this device when storage is available. They are not sent to a server. Export a backup before clearing browser data. Exports are ordinary, unencrypted JSON files; use aliases and avoid sensitive information. Changes detected in another tab block saves until you reload or explicitly replace the workspace.

The prototype supports up to 48 requests, 8 equipment types, 20 units per type and a 31-day window. It has no multi-device sync, authentication, calendar integration, background inventory feed or runtime AI service.

Example and authorship

The film-club example is fictional. Differences between its plans demonstrate behavior on that input, not measured benefits at a real lending desk.
